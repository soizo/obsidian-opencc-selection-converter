# Project Guidelines

- UI must feel native to Obsidian.
- Design for low entry barriers and a high capability ceiling: keep common actions simple and reveal advanced options only when needed.
- Keep copy short; hide implementation details unless they help the user act.
- Preserve safety, accessibility, advanced controls, and non-UI behavior.
- Verify UI changes in Obsidian, including narrow windows and both themes.
- Make focused local commits when requested. Never push or include unrelated changes.
