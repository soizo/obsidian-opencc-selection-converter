# 需求确认记录

状态：[书面设计](superpowers/specs/2026-10-02-opencc-selection-converter-design.md)已获确认；[实施计划](superpowers/plans/2026-10-02-opencc-selection-converter.md)待审核，尚未开始插件实现。

## 已确认

- 首版目标为 Obsidian 桌面端及移动端；未经实测的平台不能声称已验证。
- 在源码模式、实时预览中选择内容并转换；不要求阅读模式的选区转换。
- 入口包括右键菜单、命令面板及快捷键。没有选区时提示，不自动转换整篇笔记；转换支持撤销。
- 根据 Markdown 显示语义区分可见文本、隐藏内容及结构语法，再映射回源码。不能直接把选区当普通字符串转换，也不能用渲染结果覆盖源码。
- 例如链接的显示文字可转换，链接定界符和目标地址保持原样；转义后的可见括号可转换。如方案将方括号转换为全角括号，`\[说明\]` 应写回 `【说明】`，不是保留多余反斜线。
- 不改变选区外内容。写回须保护结构，避免转换结果意外成为 Markdown 语法；加载、映射或转换失败时保留原文。
- 行内代码、代码块、引用和 LaTeX 应具有可配置的区域转换策略：始终转换、仅选区完全位于内部时转换、始终跳过。六类设置分组以已批准设计第 5.1 节为准。
- 默认采用“仅选区完全位于内部时转换”：选区跨越正文和受保护区域时，转换选中的正文，跳过受保护区域，不取消整次操作。引用及 LaTeX 适用同样的跨边界原则。
- LaTeX 视为更多层的嵌套区域，不另设“只转换文本命令内容”的特殊策略。区域规则逐层生效：父区跳过则其内部整体跳过；父区允许仍需检查子区策略。结构语法与可见内容仍需区分。
- OpenCC 词组匹配跨越加粗等行内格式边界，按连续可见文字整体匹配。例如 `软**件**` 应能命中“软件”词组，而不是将“软”“件”分别转换。
- 默认在每次实际转换时检查等长要求，长度变化则整次不写入并提示；不因词典存在本次未使用的变长词条而拒绝添加方案。
- 提供“强制”设置以允许长度变化；跨格式且无法唯一确定归属时，替换文字继承原词组起始处的格式。强制只放宽长度限制，不绕过区域保护、选区边界和语法安全检查。
- 提供手动检查按钮，以便主动检查方案的等长风险；检查不修改笔记，也不替代每次转换时的检查。
- 真正支持 OpenCC JSON 配置、所引用词典及配置定义的完整流程，不要求用户改写为替换表；不支持的格式、配置或缺失依赖必须明确报告。
- 同时支持 URL 和 vault 文件来源。用户将 URL 依赖定位的设计交由实现方选择：默认相对配置地址自动解析，另提供词典路径至实际 URL 的覆盖映射。
- 多方案管理支持名称、添加、编辑、删除、切换、默认方案及直接指定方案转换；常用方案有独立命令，可分别绑定快捷键。
- URL 资源成功加载后缓存复用，可手动刷新；刷新失败保留上次可用版本并展示状态。vault 配置与词典也可方便地重新加载。
- 清楚展示配置来源、下载资源清单、可用状态和失败原因。选中文本在本地转换，不上传。
- 保留换行与格式，覆盖中文、标点、多行和较长选区。

## 设计已明确、仍需实现验证的边界

- LaTeX 采用固定语法集合及嵌套区域，未知宏在实际选中转换时明确拒绝，不能猜测源码映射。
- 代码内允许时转换选中代码字符，保护外围栏，不保证编程语言语义。
- 六类区域逐层应用三种策略；部分选中转义/实体等完整单元且转换会变化时拒绝写入。
- 每次实际替换及最终结果按 Unicode 码点检查等长；不能用变长、变短抵消后的总长冒充安全映射。
- 手动检查区分完整等长、潜在风险和不完整；不能把抽样通过宣称为任意输入保证。
- 物理换行、受保护区域及块级边界中断匹配，行内格式边界不中断。
- Obsidian 特有语法与无别名链接的边界按设计第 5.2 节实现。
- 用户的真实 URL/vault 配置样例尚未提供。已有 WASM 包的部分能力与桌面编辑器已通过 CLI 探针验证；自有引擎绑定、插件集成和移动真机仍未验证。
