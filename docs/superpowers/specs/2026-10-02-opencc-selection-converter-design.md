# OpenCC Selection Converter 设计

状态：本书面设计已获用户确认；[实施计划](../plans/2026-10-02-opencc-selection-converter.md)待审核。尚未开始插件实现。

需求依据：[需求确认记录](../../requirements.md)。技术依据：[可行性验证](../../feasibility.md)。本文的“支持”描述首版交付目标，不代表已经实现或完成平台验收。

## 1. 目标与不可破坏的约束

在 Obsidian 编辑模式中，按真实 OpenCC 方案转换选区的可见文字，再安全写回对应 Markdown 源码。自订方案是核心功能，不把 JSON 转换链降级为简单替换表。

必须满足：

1. 没有选区时只提示；不自动转换全文。
2. 选区外源码逐字不变，未参与转换的隐藏内容、链接目标和结构语法受到保护。
3. 配置、依赖、转换、映射或提交前检查任一失败，整次操作不写入。
4. 正常跳过受保护区域不是失败：其余合格文字继续参与同一次操作。
5. 全部结果准备好后一次编辑器事务提交；一次撤销恢复整次转换，且不合并相邻用户输入。
6. 笔记正文只在本机主线程与插件 Worker 之间传递，不上传，不写入缓存或诊断日志。
7. 不静默忽略不支持的 OpenCC 配置、依赖格式或无法映射的选中内容。

非目标：阅读模式写回、批量转换文件、自动后台转换、跨笔记改写、远程执行代码、任意 TeX 宏解释器、第三方插件生成内容的通用反向映射。

## 2. 平台与兼容边界

| 场景 | 首版目标与限制 |
| --- | --- |
| 桌面源码模式、实时预览 | 支持，两个模式执行同一转换规则 |
| Android/iOS 编辑模式 | 目标支持；运行时不依赖 Node/Electron/系统 OpenCC |
| 阅读模式 | 不修改；命令提示切换编辑模式 |
| 移动端入口 | 命令面板及用户配置的移动工具栏命令；有硬件键盘时可绑定快捷键；不依赖桌面右键手势 |
| 桌面右键 | 编辑器菜单中提供默认方案及选择方案入口 |
| 多光标、多个不连续选区 | 首版明确提示仅支持一个连续选区，不选取其中之一偷偷处理 |
| Canvas、PDF、第三方编辑器 | 首版不支持，不根据全局活动笔记猜测写入位置 |

首版 `minAppVersion` 采用已经验证环境的 1.13.7，不宣称兼容未测的旧编辑器版本。插件设计面向两端；发布说明分别列出桌面 CLI、移动模拟与真机证据。只有桌面 CLI 时，Android/iOS 标注“未真机验证”，不写成“全平台已验证”。

## 3. 架构和职责

使用 TypeScript 与 Obsidian 原生 UI。采用简单打包工具构建主入口与 Worker；不引入 React、独立组件系统、服务器或原生 Node 绑定。

四个职责边界：

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| Obsidian 接入 | 命令、菜单、方案选择、设置、捕获编辑状态、单事务提交 | 不自行实现词典匹配 |
| 源码投影 | 语法识别、嵌套区域、可见文字、字符来源、格式回写及校验 | 不下载资源，不写文件 |
| 方案资源 | 配置验证、依赖定位、下载、vault 读取、完整快照与状态 | 不接收笔记正文 |
| 引擎 Worker | OpenCC 配置执行、真实匹配追踪、词条检查、取消及销毁 | 不联网，不访问 vault |

不要求为每项职责建立接口/类层级；优先普通模块与明确的数据结构。插件常驻一个 Worker，转换/校验/词典检查按任务排队，最多保留一个活动转换器；下载可并行准备。取消正在执行的任务会销毁 Worker，队列中其他任务在新实例上重新检查有效性后执行。插件卸载时取消任务并释放 Worker、Blob URL、转换器和监听器。

运行路径：捕获选区与文档版本 → 取得已验证快照 → 生成可见文字和区域树 → Worker 执行完整 OpenCC → 验证等长与映射 → 生成最小源码 edits → 验证结构及原文版本 → 一次性提交。

## 4. OpenCC 引擎与配置

### 4.1 核心与来源

以官方 `BYVoid/OpenCC` 1.4.2 为初始固定版本，锁定源码提交与构建工具链，编译为浏览器/Worker WASM。保留 Apache-2.0 及随附依赖的许可、NOTICE 和必要署名。

增加最小绑定：加载/销毁转换器、转换并返回逐次匹配范围、枚举词典检查记录。必要的上游补丁单独保存，不在 JavaScript 重写匹配顺序、分词和候选选择算法。

现有 `opencc-wasm@0.13.1` 仅作为已验证的可行性参考，不把它的高层自动 CDN 下载接口直接用于产品。不能把其阶段级 inspect 数据误当成逐次词典命中偏移。

引擎代码和 WASM 随发布文件本地打包，不运行时从方案 URL 下载 JS/WASM。分发形式须覆盖 Obsidian 常规插件安装流程；若不能依赖额外 `.wasm` 文件自动安装，将引擎二进制打包进主发布资产并按需解码。

### 4.2 首版配置集合

| 配置 | 处理 |
| --- | --- |
| `name`、`normalization`、`segmentation`、`conversion_chain` | 按固定版 OpenCC 的有效语义执行；不丢阶段 |
| 缺省 segmentation | 使用核心本身的无显式分词行为 |
| `mmseg` | 使用原生实现及其词典 |
| `text`、`ocd`、`ocd2` | 交由原生解码；破损、旧二进制不兼容等情况明确报错，不降级为空词典 |
| `inline`、嵌套 `group` | 保留条目、顺序和 `match_policy`；缺省策略按固定版核心处理 |
| 多候选值 | 保留原生默认候选选择；不把候选字符串合并成一个目标 |
| `may_output_tofu` | 按原生库默认包含策略执行，并展示警告；不悄悄去掉这些词典 |
| 注释、尾逗号 | 接受固定版原生解析器接受的 JSON 扩展，资源发现阶段也必须一致 |
| Jieba 或其他非 mmseg 分词插件 | 首版明确不支持，不替换为 mmseg；若真实方案需要，作为待用户批准的扩展范围 |
| 未知字段、类型、非法字段值 | 在宿主验证阶段明确失败，显示配置路径；不能只依赖核心的 schema warning |

“完整执行方案”指上述支持集合内的所有阶段与依赖都执行，不是承诺加载任意本机动态插件。配置兼容性必须通过官方样例及自订多阶段样例验收，不能只检查 schema。

### 4.3 匹配追踪与等长

所有长度判断按 Unicode 码点数，不按 UTF-8 字节或 JavaScript UTF-16 code unit。源码位置仍使用编辑器要求的 UTF-16 偏移，并维护明确的转换表。拒绝包含孤立代理项或 NUL 的输入，避免编码或 C 字符串截断。配置和 text 词典使用 UTF-8 严格解码；原生输出中的非法 UTF-8 或 NUL 也必须报错，不用替代字符掩盖损坏。

每次真实字典命中记录阶段、输入范围、输出范围、词典标识与所选候选；未匹配原样输出的范围也保留来源。跨 normalization 和转换链逐层合成来源关系。追踪输出必须与未加追踪的核心转换输出完全一致。

默认严格等长：本次实际使用的每次替换及最终可见文本都必须等长。即使一次变长被另一次变短抵消、总长度未变，也拒绝整次写入。该策略比只比较整段长度更严格，以防内部格式错位；配置仍可添加，未用到的变长词条不影响转换。

强制模式只关闭等长限制。存在一对多/多对一映射时，输出继承原词组起始字符的格式来源；多阶段映射递归追溯到原文。强制模式不关闭区域、选区、链接目标、语法及并发检查。

## 5. 可见文字、区域与写回

### 5.1 区域策略

设置按下列类别分别保存：行内代码、代码块、引用、行内公式、块级公式、公式子区域。每项提供：

- 始终转换：允许选中的内部文字进入后续检查。
- 仅选区完全位于内部时转换：默认值。
- 始终跳过：即使从内部发起也不转换。

区域有完整源码范围，包含自己的定界符，但定界符本身不作为普通文字转换。“完全位于内部”定义为原始选区起止均处于同一个区域的源码范围内；选中整个区域也算位于区域内。不因移除隐藏字符而重新缩小选区来绕过规则。

由外向内逐层判断，使用原始选区而非裁剪后的子选区。父区跳过则全部子区跳过；父区允许不能覆盖子区保护。同级两个区域不能合并成一个区域以通过内部判定。

示例：

| 选区 | 默认行为 |
| --- | --- |
| 单个代码块内的部分文字 | 转换所选代码内容；围栏和语言标记不动 |
| 正文跨到代码块 | 正文转换，代码块不动 |
| 横跨两个代码块 | 两个块均跳过 |
| 完全位于引用中，但跨越引用中的行内代码 | 引用普通文字转换，代码跳过 |
| 完全位于 LaTeX 一个花括号子区内 | 按父层及该子区规则转换可映射内容 |
| 选中整条含多个子区的公式 | 默认仍跳过不满足内部条件的子区；要转换整条公式的这些子区，应将其类别设为“始终转换” |

LaTeX 使用同一递归规则，不单独限定为“只处理 text 命令”。

### 5.2 Markdown 投影

利用 Obsidian 的 CM6 编辑器扩展和语法信息识别上下文，建立自己的轻量区域/文字来源表示；不把 DOM textContent 当作可写回的源码。探针中的内部 state 数组访问不进入产品。

每个可见文字单元记录：显示字符、完整源码范围、格式上下文、区域链、编码方式（普通、反斜线转义、实体或受支持的数学符号）。对实体/转义等一个显示字符对应多个源码字符的情况，只有完整源码单元在选区内才允许改动；部分切中且确实需要改变时，整次拒绝并提示扩展选区。

普通段落中，加粗、斜体、删除线、高亮及链接显示文字之间的格式边界不打断匹配，例如 `软**件**` 命中“软件”。不跨物理换行、段落、表格单元格、公式结构边界或被跳过区域拼词。原有换行及缩进保持原样，不将视觉软换行误当成删除换行的许可。

首版语义：

| 内容 | 处理 |
| --- | --- |
| 正文、标题、列表、表格单元格、普通行内格式 | 转换可见文字，保护结构标记；表格管道等需上下文转义 |
| Markdown 链接、带别名的 wikilink | 转换显示文字，目标及 title 属性不动 |
| 无别名 wikilink | 仅当整个引用被选中时允许创建显示别名，保留目标；部分选中且转换会改变目标时拒绝，不自动重命名链接 |
| 自动链接、裸 URL | 作为链接地址保护，不改网址，不自动展开为新链接语法 |
| 图片与嵌入 | 保护整个引用，不修改目标文件、图片属性或不可反向定位的渲染内容 |
| HTML 注释、Obsidian `%%` 注释、YAML frontmatter | 隐藏/元数据区域，不转换 |
| Callout | 归入引用；保护类型标记，转换显式标题和正文；自动生成的标题没有可写源码，不生成替换 |
| 脚注 | 正文中的脚注引用标记不动；定义正文仅在其自身被选中时参与转换，不追踪到远处定义 |
| 原始 HTML、自定义渲染语法 | 首版作为不支持的映射结构；若属于本次应转换内容，明确拒绝，不静默改源码 |

### 5.3 代码与 LaTeX

代码内部是文字区域：允许时按所选原始代码字符转换，不解析其编程语言，不保证转换后代码仍可执行。若结果引入关闭围栏/行内代码的定界符，且无法在当前选区内安全表示，拒绝整次操作；不修改选区外围栏。

LaTeX 首版建立固定的可映射语法集合：普通字符、数字、可见运算符、转义标点、花括号组、上下标、`\frac`、`\sqrt`（含可选根指数）；文字/字体命令先支持 `\text`、`\textrm`、`\textbf`、`\textit`、`\mathrm`、`\mathbf`、`\mathit`、`\mathsf`、`\mathtt`、`\mathbb`、`\mathcal`、`\operatorname`。花括号组及上下标/分式参数形成子区域；结构命令不作为普通字符串交给 OpenCC。

命令渲染出的可见符号只有在有明确的源码编码映射时才可转换。初始符号表覆盖 `\times`、`\cdot`、`\pm`、`\mp`、`\div`、`\le`/`\leq`、`\ge`/`\geq`、`\ne`/`\neq`、`\infty`，以及标准希腊字母命令；命令名自身不参与转换。写回使用原命令或等价的受支持编码，不重新解释任意输出为 TeX。

未识别的宏、宏定义、复杂环境、跨文件宏或动态扩展一旦属于本次应转换内容，整次拒绝并报告位置；已按区域规则跳过的部分不触发额外错误。

这不是完整 TeX 实现。公式的“更多层区域”遵循统一策略，但源码投影能力必须逐种语法用 CLI 验收，不以猜测或宽泛正则宣称支持全部数学内容。

### 5.4 序列化安全

仅改动实际变化的文字单元；未变文字不重排、不归一化、不重新格式化。普通 Markdown、代码和数学上下文使用不同编码规则。例如 `\[说明\] → 【說明】` 可以去掉不再必要的转义；转换产生 `[` 等语法字符时，用正确转义保持它是文字。

强制模式下，若一个跨格式词组合并为较短结果，可清除完整位于选区内、已变空的纯样式包装，例如 `甲**乙** → 丙`。不为此删除链接目标、代码或数学结构；也不能清理选区外的格式标记。无法同时满足起始格式继承和结构保护时，明确拒绝，不能“强制破坏格式”。

先在内存中生成候选源码并重新解析受影响的完整上下文，验证链接目标、区域结构、非目标文字、换行及选区外源码不变；允许的差异仅为目标文字与已定义的转义/显示别名/空样式包装调整。校验通过之前不触碰编辑器内容。

## 6. 方案来源、验证和缓存

### 6.1 资源定位

方案来源为 URL 或 vault 内配置文件。用户自订名称与稳定 ID 独立，重命名不改变命令 ID。

- URL：优先 HTTPS；相对依赖基于所填配置 URL 的目录解析，绝对依赖保留地址。高级设置可提供依赖基址及“原词典路径 → 实际 URL”覆盖映射，不要求用户修改 JSON。
- URL 重定向：不假定 Obsidian 请求 API 一定暴露最终 URL。相对路径始终使用界面明示的基址，不暗中猜测跳转后的目录；迁移目录的地址须填写新直达 URL、依赖基址或覆盖映射。HTML 仓库页、分享页不是 JSON 资源，明确报错。
- vault：相对配置所在目录解析，允许 `../` 指向 vault 内其他位置；归一化后不得越过 vault 根。不接受系统绝对路径或读任意本机文件。
- 来源不隐式跨界：远程配置不能引用本地 vault 文件；本地配置不会隐式触发网络下载。若需远程词典，应使用明确的 URL 方案/覆盖设置。
- 不接受带用户名密码的 URL，也不执行 `file:`、`javascript:`、`data:` 等方案地址。不提供凭据管理功能。非 HTTPS 来源必须显式确认风险，不能由远程配置自动降级。
- 使用无损的内部路径映射把资源放入方案独立的虚拟目录；修改的是内部副本的文件定位，不修改原始 JSON/词典，不改变顺序或转换规则。

添加 URL 的动作先获取配置自身；解析后列出将下载的所有去重资源及原始引用位置，确认后加载依赖。跨域资源也明确列出。不从来源网页自动抓取更多文件，不加载任意动态库。正常转换只使用已加载快照，不触发网络。

### 6.2 验证与状态

验证包含：配置语法及已知字段 → 完整依赖发现 → 文件存在/请求状态 → 格式及资源限制 → 原生引擎成功加载。错误同时显示方案、阶段、JSON 路径或词典路径及原因；不要只显示“加载失败”。

状态：未加载、加载中、可用、源文件已变更、使用旧缓存（刷新失败）、不可用。错误与警告分别显示；含变长词条的方案仍可以是可用状态。

vault 文件监听只把对应方案标记为已变更；用户点“重新加载”才切换快照，不在每次输入时重建引擎。刷新与转换可并行准备，但正在转换的任务始终绑定开始时的完整快照。

### 6.3 完整快照与失败恢复

配置原文、资源字节、来源映射、哈希、引擎版本和验证结果共同组成一个不可变快照。缓存放在插件自己的目录，通过 Vault Adapter 读写；设置数据仅保存方案元数据、策略和快照引用，不塞入大块词典。

新版本先写独立候选目录，校验全部资源并在 Worker 成功加载，最后写完整性清单作为提交标记，再切换活动引用。旧版本在新版本验证成功前不删除。

不能假定手机文件系统或单次 JSON 写入天然原子。重启时校验提交标记、资源哈希和来源身份，只恢复完整快照；损坏的活动引用不能掩盖上一个完整版本。候选写入中断不影响旧版。引擎版本变化时，必须用当前引擎重新验证缓存后才可使用，不能沿用旧引擎的可用标记。每方案保留当前和上一份可用版本，其余由该插件清理，不触碰源配置/词典。

刷新失败：旧快照仍可转换，界面和操作提示显示旧版及失败原因。首次加载失败：不可用，不注册一个假装可工作的默认方案。

修改方案来源或依赖覆盖后，新定义先作为待验证草稿。未通过前当前活动定义和快照不变，界面明确标注“仍在使用旧来源”，不把旧词典冒充新来源。删除方案撤销其命令及插件缓存，不删除用户源文件；删除默认方案后要求重新选择默认方案，不擅自改用另一套。

## 7. 手动检查与运行时保护

每个方案提供“检查等长性”按钮，检查绑定到该方案的当前快照，不修改笔记。枚举 normalization 和转换阶段使用的词典，保留词典/阶段/条目来源；分词词典只用于分段的候选值不误算为实际输出。

结果分三类：

- **所有已检查的有效转换条目等长**：只有完整枚举了支持集合内全部有效转换条目，才能声明该快照通过条目级等长检查。
- **存在潜在变长条目**：列出输入、默认目标、长度差和来源；条目未必会被当前选区命中，不因此禁用方案。
- **检查不完整/失败**：资源限制、无法枚举或不支持能力时，清楚列出未覆盖部分；不显示绿色“通过”。

可提供对风险条目的完整链复查作为诊断，但不能把有限样例覆盖称为任意输入证明。检查后的方案刷新会使旧检查结果过期；运行时等长与映射检查始终执行。

初始安全上限：配置 2 MiB；单依赖 64 MiB；单快照 128 MiB、256 个资源；配置嵌套深度 32；单次选区 200,000 Unicode 码点；单次输出 8 MiB、追踪数据 64 MiB；WASM 线性内存最多 256 MiB；单资源请求 30 秒、单次 Worker 工作 30 秒（不含排队时间）。桥接层在生成输出/追踪时检查预算，不能等巨大结果传回主线程后才判断。超过则明确拒绝/报告检查不完整，不截断内容。这些是独立保护边界，不保证所有资源同时达到各项上限仍能加载，也不是已验证的性能承诺。

请求层若没有流式读取或取消能力，大小限制只能在接收后校验，不能宣称限制了下载途中峰值内存。请求超时后忽略迟到结果，永不切换快照。UI 应能取消加载/检查/转换；取消 Worker 任务时销毁相应实例，后续从完整快照恢复。

## 8. 编辑状态与提交

所有入口汇入同一函数，捕获实际触发命令的编辑器实例、文件身份、不可变文档状态、单个选区及方案快照 ID。选区外不变以捕获的编辑器源码为基准；插件不另做磁盘整文件重写或换行归一化。Obsidian 自身的文件编码/换行持久化行为须单独记录，不能把引擎的 CRLF 测试当作编辑器磁盘字节保真证明。选择方案弹窗使用此前捕获的选区，不依赖弹窗关闭后的焦点猜测。

提交前再次检查：文件身份未变、编辑器仍存在、文档未发生修改、原始选区未被用户更改、方案未被删除、任务未取消且仍为当前任务。任一不满足则不写入并提示重试。用户修改后又撤销为相同文本也算版本变化，不能只比较选中文字。

同一编辑器只允许一个待提交任务，后发任务取消先发任务；方案切换不改变已开始任务的引擎。跨窗口或同步修改也必须触发过期检查。

提交采用 CM6 的一次 transaction，并显式隔离 undo 历史边界。写入尽量是多个小 edits，而不是替换整篇笔记。转换结果仍选中原选区对应的新范围；无变化时只提示，不制造撤销记录。

动态方案命令使用稳定 ID。首次加载失败仍可列出管理入口，但转换入口必须说明该方案不可用。快捷键交给 Obsidian 原生设置管理，不预占用户键位。

## 9. 设置与交互

原生设置页分两部分：

1. **方案**：名称、来源、可用状态、活动版本/最近成功时间、失败原因；默认按钮；编辑、刷新/重新加载、检查等长性、删除。高级字段折叠显示依赖基址与词典 URL 覆盖。
2. **转换规则**：六类区域策略；“允许变长转换（强制）”开关，默认关闭，旁注明格式继承与仍受保护的边界。

命令：用默认方案转换、选择方案转换，以及每个已添加方案的独立转换命令。右键仅提供默认与方案选择，不塞满所有管理功能。没有默认方案时引导选择，不悄悄选第一项。初始没有方案，不自动联网获取预设，也不为首版打包整套官方词典；用户从添加自己的 URL/vault 方案开始。

添加 URL 时展示隐私说明：只请求配置和依赖资源，服务器会看到正常资源请求；选中文本不会发送。资源清单可在方案详情查看。错误提示不泄露 URL 中可能存在的查询凭据，日志不保存选区正文。

删除方案需确认；不可逆的是插件中的方案与缓存，不影响用户原始文件。加载、刷新、检查期间提供进度状态与取消，按钮避免重复提交；错误可以重试，不需要重启 Obsidian。

## 10. 验收方式

全部行为测试通过 Obsidian CLI，在专用 `OpenCC-Selection-Converter-Test` vault 执行。测试驱动必须验证 vault 身份；不得读写其他 vault。测试脚本可以在 CLI 中运行真实插件、CM6、Worker 和网络 fixture，但不得用 mock 结果替代关键集成路径。

构建、类型检查和静态诊断是构建质量检查，不冒充 CLI 功能验收。CLI 返回码可能为 0 而 eval 内部失败，测试驱动必须读取结构化结果并断言。

最低验收矩阵：

| 范围 | 必测情形 |
| --- | --- |
| 入口 | 右键、默认命令、方案选择、独立方案命令、快捷键配置关联；无选区；阅读模式 |
| 编辑安全 | 源码/实时预览；前后哨兵逐字不变；单次 undo/redo；相邻用户输入单独撤销；弹窗后焦点变化；异步文档修改与取消 |
| 可见文字 | `软**件**` 跨格式词组；转义括号；链接文字/目标；别名；实体；部分语法单元；隐藏注释/frontmatter |
| 区域 | 六类策略；父允许子拒绝、父拒绝子允许；横跨两个区域；引用中代码；数学多层参数 |
| LaTeX | 普通变量、文字参数、嵌套分式/上下标、受支持符号；未知宏拒绝且全文不变 |
| 格式保护 | 转换结果产生 Markdown 标记；代码结束符；强制合并样式；不允许跨选区清理；序列化后结构验证 |
| OpenCC | 官方配置；normalization；无分词/mmseg；group 两种策略及嵌套；多候选；text/ocd/ocd2/inline；未知字段、插件与损坏词典 |
| 等长 | 本次未命中变长条目可成功；命中则默认拒绝；总长相等但内部偏移拒绝；强制继承起始格式；补充平面字符 |
| 检查按钮 | 完整/风险/不完整；词典与阶段定位；刷新后旧检查过期；不能以样例通过替代完整检查 |
| URL | 配置及相对/绝对依赖、覆盖映射、依赖基址；请求资源清单与计数；转换不发请求；下载失败、不透明跳转基址提示 |
| 缓存 | 首次失败；刷新失败旧版可用；进程重载后离线复用；中断候选写入；哈希损坏；来源编辑失败不冒充新来源 |
| vault | 配置及词典修改标记、重新加载、允许的 ../、越界拒绝、文件丢失 |
| 稳定性 | 中文、标点、多行、50,000 字及明确上限；不切断词组规避内存问题；WASM 出错后实例废弃；进度取消 |
| 移动目标 | CLI 移动模拟检查布局和入口；浏览器模式 Worker 无 Node 依赖；真机没有证据时保留未验证标识 |

引擎追踪路径与原生正常转换结果做差分；使用正式 WASM 中的两条调用路径在 CLI 内比较，而不是依赖本机 `opencc` 命令充当唯一测试。现有探针只是前置证据，不能当作整个矩阵已完成。

## 11. 交付物与审核边界

交付目标：可安装插件发布文件、源码、固定版引擎构建与补丁、许可文件、使用/兼容说明、CLI 验收脚本及结果记录。

保留现有需求和可行性记录，不覆盖先前证据。每个实现阶段本地提交；不推送，不创建额外分支，不启动子代理。

本设计明确提出的首版限制包括：非 mmseg 分词插件、多选区、阅读模式、任意 TeX 宏/原始 HTML/第三方渲染反向映射均不支持；URL 相对资源使用明示基址；严格等长按实际替换而非只看最终总长度。这些边界已随本文获用户确认。实施计划已据此编写，待用户审核后执行；方案、缓存和编辑器代码尚未开始实现。
