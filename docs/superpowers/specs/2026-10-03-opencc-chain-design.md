# OpenCC 转换链与大陆繁体预设

## 目标与已确认范围

用户要求支持 OpenCC chain，并添加 `t2gov` 和 `s2gov = s2t → t2gov`；用户已确认采用可自由组合多个方案、可调整顺序、保存后一次执行的界面方案。

- `t2gov`：繁体 → 大陆繁体，直接使用 TerryTian-tech 仓库的配置与词典。
- `s2gov`：现有 OpenCC 官方 `s2t` 完整运行后，再完整运行上述 `t2gov`。
- 保留离线缓存、严格等长检查、Markdown 保护、取消操作和一次撤销；任何阶段失败都不写入文档。
- UI 沿用 Obsidian 原生组件，中英文文案简短，不引入 UI 库或新的运行时依赖。

## 现有实现与必须保留的语义

`src/schemes/config.ts` 已支持单个 OpenCC 配置中的 `normalization`、`segmentation` 和 `conversion_chain`。目前方案、缓存快照和 Worker 请求均以一个完整配置为单位。

多个完整配置不能通过简单拼接 `conversion_chain` 实现等价串联：后一个配置必须在前一个的输出上重新执行自己的归一化和分词。现有 `trace/segment-boundaries` 测试也表明，分词边界会影响后续转换阶段的匹配。

因此需要扩展方案与快照表示，并在现有 Worker 路径中顺序执行完整配置；不改动 OpenCC 原生算法，不另建转换引擎。

## 方案

### 1. 转换链定义与编辑

新增「转换链」来源，与预设、库内文件、URL 并列。用户从已有单一方案中添加步骤，用上移、下移和移除按钮调整顺序；链名称可编辑，空名称由步骤名称生成。

首版范围：

- 转换链至少包含两个步骤，最多 16 步；单个方案仍使用原有入口。
- 允许重复使用同一单一方案，因为连续转换可能具有实际语义。
- 不支持链中嵌套链，避免循环引用和递归资源扩张。
- 保存时复制各步骤的来源定义及可用快照，形成独立、完整的链快照。不依赖原方案在未来仍然存在。
- 后续编辑、刷新或删除原方案不会悄悄改变已保存的链。链可编辑步骤，显式刷新时按所保存的各步骤来源重新加载。
- 创建和仅改名可以使用现有离线快照；更换步骤或调整顺序必须生成相应的新快照。

以上生命周期行为是实现默认值，应在转换链编辑界面用一句简短说明告知用户。

### 2. 快照与缓存

扩展现有方案和快照类型以表示有序的完整配置；继续复用资源加载、哈希校验、不可变快照和双槽元数据提交机制。

- 旧单配置方案与缓存无需用户迁移，继续可读和可转换。
- 每一步资源具有隔离的虚拟路径，避免不同方案中同名词典冲突。
- 链的来源身份包含步骤顺序及每步完整来源参数；改名不改变来源身份。
- 资源数量、总字节数、配置大小与执行时间限制在整条链层面有效，不能按步骤重复获得预算。
- 本地源文件变化、HTTP 精确 URL 授权、加载取消及刷新失败保留旧快照的规则继续有效。
- 整条链加载与验证成功后才发布；不暴露部分成功版本。

### 3. 执行与安全

在同一个 Worker 作业中按顺序执行每个完整配置，沿用原生转换与 trace 接口。

- 后一步输入等于前一步完整输出，保留每步归一化和分词。
- 将每步 Unicode 标量来源映射复合回原始输入；所有实际匹配记录保留，并带步骤位置。
- 严格模式检查所有步骤中的实际匹配长度。先扩长再缩短到原长度也必须拒绝，不能只比较最终长度。
- Force 模式仅放宽长度限制，仍使用既有来源映射、Markdown 序列化和候选重解析检查。
- 每步原生句柄及文件在成功和失败路径均释放；整条链仍受现有 Worker 超时与取消机制控制。
- 等长性审计汇总各步骤：任何不完整则总体不完整，否则存在风险则总体有风险，全部等长才报告等长。
- `main.ts` 现有最终一次提交机制保留；转换中途不会修改笔记。

### 4. 大陆繁体预设

上游：<https://github.com/TerryTian-tech/OpenCC-Traditional-Chinese-characters-according-to-Chinese-government-standards>

已核对：

- `t2gov/t2gov.json` 使用文本词典 `CJK_Compatibility_Ideographs.txt`、`TGPhrases.txt`、`TGCharacters.txt`，与当前配置解析器兼容。
- 上游许可为 Apache-2.0。
- 上游也有自己的 `s2t.json`，但它不是本次 `s2gov` 的第一步；本次明确沿用插件现有 OpenCC 官方 `s2t`。

实现时固定上游提交，以现有 CDN 加载方式获取配置及相对词典；首次添加需加载，成功后完整缓存供离线使用。记录准确来源和许可证，不把大陆繁体方案标成 OpenCC 官方预设；预设入口改用不暗示全部来自 OpenCC 官方的名称。

`s2gov` 复用通用链实现，不写专用字符替换规则。两个新预设均可像现有方案一样设为默认、分配命令与快捷键。

## 预计改动区域

- `src/schemes/model.ts`、`resources.ts`、`store.ts`：链定义、资源准备、快照持久化与恢复。
- `src/engine/worker.ts` 及必要的类型：完整配置顺序执行、trace 复合、审计汇总和总预算。
- `src/scheme-modal.ts`、必要的设置展示及中英文 locale：预设与链编辑。
- `tests/cli/`：引擎、缓存、映射、编辑器和设置回归；沿用现有测试设施。
- `README.md`、第三方声明及验证记录：使用说明、来源和验证证据。

不做无关重构，不修改原生 OpenCC 实现，不改变默认区域规则，不自动提交或推送。

## 验收与验证

先写失败测试，再实现：

1. 两个完整配置串联的结果等同于分别顺序调用；专门覆盖后一步重新分词和归一化，防止错误的配置拼接。
2. 同名但内容不同的词典互不覆盖；步骤顺序与重复步骤均按定义生效。
3. 扩长后缩短仍被严格模式拒绝；Force 模式保留正确来源映射和现有 Markdown 安全边界。
4. 失败、取消和过期选区均不写入；成功转换一次撤销恢复。
5. 链快照重启后可离线使用，删除原方案不影响已保存的链；刷新失败保留旧版本，旧单方案缓存仍可用。
6. 两个预设真实加载、转换并验证代表性大陆繁体样例；`s2gov` 与官方 `s2t` 再接上游 `t2gov` 的结果一致。
7. 在专用测试 vault 内验证新增、编辑、重排、删除步骤、默认项和命令，以及双主题和窄窗口，无横向溢出或不可触达按钮。
8. 运行 `npm run check`、相关专项及最终完整测试矩阵和正式包验收；未完成或环境阻塞的验证明确记录，不以桌面模拟替代真机结论。
